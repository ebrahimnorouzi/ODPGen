Modeling constraints:
- Do not add concepts or axioms not grounded in the scenario or CQs.
- Declare every class with `a owl:Class`, every property with `a owl:ObjectProperty`, `a owl:DatatypeProperty`, or `a owl:AnnotationProperty`.
- Do NOT create individual instances (e.g. `:SomePerson a :Person`); output schema axioms only.
- Every class and property must have rdfs:label and rdfs:comment annotations.
- Declare a mandatory ontology header: `:Ontology a owl:Ontology ; rdfs:label "..." ; rdfs:comment "..." .`
- Keep the ontology minimal and reusable.

Self-validation checklist (evaluate each item as PASS or FAIL with a one-line reason):
1. Turtle syntax is valid (no missing dots, brackets, or semicolons).
2. All prefixes used in the body are declared at the top.
3. Every property with a domain or range declaration uses only classes defined in this ontology or well-known external vocabularies.
4. No two classes or properties are defined with contradictory restrictions (e.g., disjoint yet subclass, or inconsistent domain declarations).
5. Every CQ is traceable to at least one class or property in the ontology.
6. No concept appears in the ontology that is not grounded in the scenario or CQs.

Output format — strictly in this order, nothing before item 1:
1. The complete Turtle ontology wrapped in a ```turtle ... ``` code block. Output this FIRST, before any explanation.
2. Validation report: checklist items 1–6 each marked PASS or FAIL with a brief reason.

Scenario:
To demonstrate the applicability of LCAnet, we instantiate the ontology network on a real-world LCA study conducted within the SmartACV project called the StorAIge study. This study is aimed at evaluating the environmental impact of a Near Memory Computing prototype based on C-SRAM technology.

The LCA study was conducted using the EIME software tool, connected to a Bill of Materials describing the electronic components of the prototype. Inventory data were sourced from two databases: CODDE (v3.00.000) and NegaOctet. Environmental impact calculations were performed using the Environmental Footprint 3.0 (EF 3.0) methodology. The resulting inventory and impact data, together with study metadata including hypotheses, parametrisation, system boundary, and actor information, were extracted and subsequently used as input data for the use case.

Competency Questions:
- What are the input and output flows of all activities?
- What is the dependency chain of activities in a system model?
- Which flow datasets come from database X?
- What are the elementary and intermediate flows associated with a given activity?
- Which flows are classified as resources, emissions, or products?
- What is the functional unit, scope, system boundary, and responsible agent of the LCA model?
- What is the impact result of a given activity or flow across impact categories?
- Which flows contribute significantly (e.g., > 2%) to a given impact category?
- What are the top contributors to an impact category for a given activity?
- What is the total amount of flow X generated within the system boundary?
