2. Scenario-requirement-to-axiom mapping

- Requirement: There is software whose requirements need to be represented.
  - Axioms:
    - `:Software a owl:Class`
    - `:hasRequirement a owl:ObjectProperty ; rdfs:domain :Software ; rdfs:range :Requirement`

- Requirement: Requirements concern both software and hardware.
  - Axioms:
    - `:Requirement a owl:Class`
    - `:SoftwareRequirement a owl:Class ; rdfs:subClassOf :Requirement`
    - `:HardwareRequirement a owl:Class ; rdfs:subClassOf :Requirement`

- Requirement: A software can require software resources.
  - Axioms:
    - `:requiresSoftware a owl:ObjectProperty ; rdfs:domain :Software ; rdfs:range :Software`
    - `:requiredSoftware a owl:ObjectProperty ; rdfs:domain :SoftwareRequirement ; rdfs:range :Software`

- Requirement: A software can require hardware resources.
  - Axioms:
    - `:Hardware a owl:Class`
    - `:requiresHardware a owl:ObjectProperty ; rdfs:domain :Software ; rdfs:range :Hardware`
    - `:requiredHardware a owl:ObjectProperty ; rdfs:domain :HardwareRequirement ; rdfs:range :Hardware`

- Requirement: Requirements may specify the type of required software or hardware.
  - Axioms:
    - `:SoftwareType a owl:Class`
    - `:HardwareType a owl:Class`
    - `:requiresSoftwareType a owl:ObjectProperty ; rdfs:domain :SoftwareRequirement ; rdfs:range :SoftwareType`
    - `:requiresHardwareType a owl:ObjectProperty ; rdfs:domain :HardwareRequirement ; rdfs:range :HardwareType`

- Requirement: Requirements may constrain characteristics/properties of required software or hardware.
  - Axioms:
    - `:Property a owl:Class`
    - `:constrainsProperty a owl:ObjectProperty ; rdfs:domain :Requirement ; rdfs:range :Property`

- Requirement: Requirements may express minimum, maximum, or exact values for a constrained property.
  - Axioms:
    - `:minimumRequiredValue a owl:DatatypeProperty ; rdfs:domain :Requirement ; rdfs:range xsd:string`
    - `:maximumRequiredValue a owl:DatatypeProperty ; rdfs:domain :Requirement ; rdfs:range xsd:string`
    - `:exactRequiredValue a owl:DatatypeProperty ; rdfs:domain :Requirement ; rdfs:range xsd:string`

- Requirement: Software requirements may express minimum, maximum, or exact version constraints.
  - Axioms:
    - `:minimumRequiredVersion a owl:DatatypeProperty ; rdfs:domain :SoftwareRequirement ; rdfs:range xsd:string`
    - `:maximumRequiredVersion a owl:DatatypeProperty ; rdfs:domain :SoftwareRequirement ; rdfs:range xsd:string`
    - `:exactRequiredVersion a owl:DatatypeProperty ; rdfs:domain :SoftwareRequirement ; rdfs:range xsd:string`

4. Intentionally excluded concepts

- Matchmaker
  - Excluded because the CQs focus on representing requirements of software and required software/hardware, not the matchmaking process itself.

- Catalogue
  - Excluded because no CQ asks about catalogue membership or catalogue structure.

- Incoming service request
  - Excluded because the CQs are specifically about software requirements, not service request modeling.

- Main software vs supporting/deployment/execution roles
  - Excluded because the scenario mentions execution/support/deployment goals, but the CQs do not require modeling distinct roles of candidate resources.

- Actual characteristics of available resources
  - Excluded because the CQs ask only for required characteristics, not observed/catalogued characteristics of candidate resources.

- DPU and GPU as explicit subclasses or individuals
  - Excluded because the scenario gives them as examples of hardware resources, while the CQs only require support for hardware types in general, which is covered by `:HardwareType`.

- Interoperability, trustworthy AI, scalable edge computing, quantum resilience, and SMARTY project structure
  - Excluded because these provide background motivation only and are not needed to answer the stated CQs.
