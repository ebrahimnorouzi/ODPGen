4. Intentionally excluded concepts

- Mike / user / person
  - Excluded because the CQs do not ask about users or agents, and the scenario only uses Mike as narrative context.

- A dedicated “solution design activity”
  - Excluded as a class because it is not needed by the CQs. The scenario mentions analysis for design, but chat analysis is sufficiently supported by `:Chat`, `:Prompt`, `:Response`, and `:analyzesChat`.

- Explicit frequency/statistics entities such as “AdoptionStatistic” or “UsagePattern”
  - Excluded because the CQs can be answered by aggregating over prompts, chats, models, tasks, and techniques without reifying statistics.

- Detailed constraint types such as “architecture constraint” or “resource constraint”
  - Excluded because the scenario only requires generic constraints plus the ability to indicate the constrained variable.

- Separate properties for “chat uses model” and “prompt submitted to model”
  - Excluded to avoid unnecessary duplication not grounded in the scenario/CQs; `:usesModel` supports both cases.

- Ordering of prompts and responses within a chat
  - Excluded because no CQ requires sequence reconstruction.

- Prompt text and response text literals
  - Excluded because the CQs ask for prompts and responses as entities and their relations, not their textual content.
