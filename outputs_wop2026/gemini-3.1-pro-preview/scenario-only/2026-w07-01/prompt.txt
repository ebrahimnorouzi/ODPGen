You are an ontology engineer. Generate an OWL ontology design pattern (ODP) in Turtle syntax from the scenario below.

Requirements:
- Stay strictly within the scenario scope; do not add concepts not implied by it.
- Use clear, self-explanatory class and property names.
- Include minimal but sufficient axioms (domain, range, subclass, disjointness where justified).
- Declare every class with `a owl:Class`, every property with `a owl:ObjectProperty`, `a owl:DatatypeProperty`, or `a owl:AnnotationProperty`.
- Do NOT create individual instances (e.g. `:SomePerson a :Person`); output schema axioms only.
- Add rdfs:label and rdfs:comment annotations to every class and property.
- Declare a mandatory ontology header: `:Ontology a owl:Ontology ; rdfs:label "..." ; rdfs:comment "..." .`

Use these standard prefixes (declare all that you use):
  @prefix owl:  <http://www.w3.org/2002/07/owl#> .
  @prefix rdf:  <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
  @prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
  @prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .
  @prefix :     <http://example.org/odp#> .

Output format — strictly in this order, nothing before item 1:
1. The complete Turtle ontology wrapped in a ```turtle ... ``` code block. Output this FIRST, before any explanation.
2. A short documentation section with:
   - Intent: one sentence on what the pattern models.
   - Covered requirements: bullet list derived from the scenario.
   - Known assumptions and exclusions.

Scenario:
We used the following running use case to scope the ontology. i. Learner may pursue goals that target skills ii. Learner may have preferences, challenges or awareness over one or more topics or skills iii. Learning objectives are aligned in relation to learner situations and may be supported by pedagogical techniques or learning resource units iv. Assessment exercises use evaluation techniques and metrics to produce results that support feedback (with source and temporal information), awareness observations or learning strategies used. These led to six modeling requirements where APLO needed to represent pedagogical organization, including frameworks, elements and their order; objective alignment across learning objectives, pedagogical techniques and learning resources; evaluation, including assessment exercises, techniques, metrics and results; feedback responses, including source and temporal information; learner context, including goals, preferences, challenges and situations; and learner awareness as topic or skill-scoped information that changes over time.
