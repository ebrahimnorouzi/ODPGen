You are an ontology engineer. Generate an OWL ontology design pattern (ODP) in Turtle syntax from the scenario below.

Requirements:
- Stay strictly within the scenario scope; do not add concepts not implied by it.
- Use clear, self-explanatory class and property names.
- Include minimal but sufficient axioms (domain, range, subclass, disjointness where justified).
- Declare every class with `a owl:Class`, every property with `a owl:ObjectProperty`, `a owl:DatatypeProperty`, or `a owl:AnnotationProperty`.
- Do NOT create individual instances (e.g. `:SomePerson a :Person`); output schema axioms only.
- Add rdfs:label and rdfs:comment annotations to every class and property.
- Declare a mandatory ontology header: `:Ontology a owl:Ontology ; rdfs:label "..." ; rdfs:comment "..." .`

Use these standard prefixes (declare all that you use):
  @prefix owl:  <http://www.w3.org/2002/07/owl#> .
  @prefix rdf:  <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
  @prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
  @prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .
  @prefix :     <http://example.org/odp#> .

Output format — strictly in this order, nothing before item 1:
1. The complete Turtle ontology wrapped in a ```turtle ... ``` code block. Output this FIRST, before any explanation.
2. A short documentation section with:
   - Intent: one sentence on what the pattern models.
   - Covered requirements: bullet list derived from the scenario.
   - Known assumptions and exclusions.

Scenario:
To demonstrate the applicability of LCAnet, we instantiate the ontology network on a real-world LCA study conducted within the SmartACV project called the StorAIge study. This study is aimed at evaluating the environmental impact of a Near Memory Computing prototype based on C-SRAM technology.

The LCA study was conducted using the EIME software tool, connected to a Bill of Materials describing the electronic components of the prototype. Inventory data were sourced from two databases: CODDE (v3.00.000) and NegaOctet. Environmental impact calculations were performed using the Environmental Footprint 3.0 (EF 3.0) methodology. The resulting inventory and impact data, together with study metadata including hypotheses, parametrisation, system boundary, and actor information, were extracted and subsequently used as input data for the use case.
