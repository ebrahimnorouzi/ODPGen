**Documentation**

**Intent:** This ontology design pattern models the relationships between symbols in a binary executable file, enabling the creation of knowledge graphs to facilitate software reverse engineering.

**Covered requirements:**

* Stay strictly within the scenario scope
* Use clear, self-explanatory class and property names
* Include minimal but sufficient axioms (domain, range, subclass, disjointness)
* Declare every class with `a owl:Class`, every property with `a owl:ObjectProperty`, `a owl:DatatypeProperty`, or `a owl:AnnotationProperty`
* Do NOT create individual instances
* Add rdfs:label and rdfs:comment annotations to every class and property

**Known assumptions and exclusions:**

* The ontology assumes that the symbol table is a collection of symbols, and each symbol has a unique name.
* The ontology excludes the representation of malware-specific behavior and dependency vulnerabilities in a software supply chain, which are mentioned in the scenario as potential future extensions.
* The ontology does not include any axioms related to the expansion of the knowledge graph to apply to finding dependency vulnerabilities in a software supply chain.
