Overview & Research Questions

ODPGen is an empirical study evaluating how well LLMs can generate Ontology Design Patterns (ODPs) from natural-language scenarios and competency questions, and how valid and useful the resulting patterns are.

What are ODPs?

Ontology Design Patterns are reusable ontology templates that encode solutions to common modeling problems. They serve as building blocks for ontology engineering — analogous to design patterns in software engineering.

An ODP defines a set of classes, properties, and axioms grounded in a real-world scenario, answerable by a set of Competency Questions (CQs).

Research Questions

  • RQ1 — How well can LLMs generate valid OWL Turtle from natural-language scenarios?
  • RQ2 — How logically consistent and free from modeling errors are the outputs?
  • RQ3 — What is the impact of prompting strategy (CQs, reasoning, constraints)?
  • RQ4 — How faithful are outputs to the ground-truth scenario?
  • RQ5 — Can models generalize to recently published ODPs unseen during training?
Core hypothesis: More structured prompting (with CQs + explicit reasoning or self-validation) should improve output quality — but may trade off with syntactic correctness for weaker models.

Prompting Strategies

Five prompt configurations systematically vary the information given to the model and the level of structural guidance. All prompts use standard RDF/OWL prefixes and require valid OWL/Turtle output.

1. scenario-only

Model receives only the domain scenario text. No CQs provided. Must infer modeling scope entirely from the narrative.

  • Tests pure scenario comprehension
  • Highest scenario coverage among configs
  • No CQ grounding → lower faithfulness

2. cq-only

Model receives only the Competency Questions (CQs). No scenario text. Must reverse-engineer the domain from requirements.

  • Highest CQ coverage (0.844 avg)
  • Also highest hallucination ratio (0.548)
  • Low scenario vocabulary coverage (0.182)

3. scenario-cq Balanced

Both scenario text and CQs are provided. Model must map scenario requirements to axioms and trace each CQ to ontology elements.

  • Best balance of CQ + scenario coverage
  • Requires scenario→axiom & CQ→axiom mapping
  • Second-highest parse success rate (39%)

4. scenario-cq-constraints Validation

Extends scenario-cq with a 6-item self-validation checklist that the model must complete before outputting the ontology.

  • Syntax, domain/range, coherence, CQ traceability, scope
  • Lowest hallucination after reasoning (0.392)
  • Lowest parse success (29%) — extra text confuses parsers

5. scenario-cq-reasoning Best Hallucination Control

Extends scenario-cq with explicit 6-step internal reasoning protocol: (1) extract requirements, (2) propose classes/properties, (3) draft axioms, (4) verify each CQ, (5) remove unsupported elements, (6) output ontology + traceability table.

  • Lowest hallucination ratio overall: 0.367
  • Good CQ coverage: 0.748 avg on successful parses
  • Best scenario coverage (0.379) among CQ-aware configs

Prompt Template Placeholders

You are an expert ontology engineer. Your task is to generate an Ontology Design Pattern (ODP) in OWL/Turtle syntax for the following scenario. ## Scenario {{SCENARIO_TEXT}} ## Competency Questions {{CQ_LIST}} ## Output Requirements - Use prefixes: @prefix owl: <...> @prefix rdfs: <...> @prefix : <http://example.org/odp/> - Declare an owl:Ontology with rdfs:label and rdfs:comment - Only model what is grounded in the scenario — avoid hallucinated domain knowledge - Provide: scenario-requirement-to-axiom mapping, CQ-to-axiom mapping

Evaluation Methodology

ODPGen uses a multi-layer automated evaluation pipeline implemented in Python with RDFLib, covering four orthogonal quality dimensions.

Layer 1 — Formal / Syntactic Quality

  • parse_success — Can the output be parsed as valid Turtle?
  • triple_count — Total number of RDF triples
  • ontology_declared — owl:Ontology header present?
  • label/comment coverage — Ratio of entities with rdfs:label / rdfs:comment
  • domain_range_ratio — Properties with rdfs:domain & rdfs:range
  • has_prefix_declarations — Standard OWL/RDF prefixes used?
  • class_count, property_count — Size of the pattern

Layer 2 — Scenario Faithfulness

  • cq_coverage_ratio — Fraction of CQs answerable by the ontology (token overlap)
  • cq_mean_token_recall — Average token recall across all CQs
  • scenario_coverage_ratio — Fraction of scenario vocabulary reflected in ontology
  • hallucination_ratio — Fraction of generated vocabulary NOT grounded in the scenario
  • ontology_vocab_size — Generated vocabulary size

Layer 3 — Semantic Similarity to Ground Truth

  • class_name_precision/recall/F1 — Name match of generated vs. ground-truth classes
  • property_name_precision/recall/F1 — Same for properties
  • class_jaccard, property_jaccard — Set-theoretic similarity
  • combined_f1 — Harmonic mean of class + property F1
  • matched_class/property_names — Exact name matches found

Layer 4 — Feasibility & Unseen Analysis

  • Each (ODP, model) pair is classified as plausible_unseen or likely_seen by comparing ODP publication date to model training cutoff
  • Confidence levels: high / medium / low based on known cutoff precision
  • Enables analysis of generalization vs. memorization
Layer 4 (Human Evaluation) — Planned: expert raters score Correctness, Completeness, Clarity (1–5 scale) via generated evaluation sheets. Data collection in progress.
Pipeline: evaluate_outputs.py → eval/formal_quality.py + eval/faithfulness.py + eval/similarity.py → results/summary.csv (364 rows × 42 columns)

Summary & Winner Analysis

Which LLM Performs Best?

★

Best Overall: Llama-3.1-8B-Instruct

  • Highest parse success: 75.7% across all configs
  • Lowest hallucination rate: 0.345
  • Consistently parseable even with complex prompts
  • Good CQ coverage: 0.729 on successful outputs
  • Most reliable and trustworthy open-source model
🥈

Best Quality When Parsed: GPT-5.4

  • Highest CQ coverage: 0.804
  • Best combined F1: 0.110
  • Perfect label/comment coverage: 1.0
  • But: 0% parse rate on reasoning/constraints configs
  • High hallucination (0.585) offsets quality gains
🥉

Best Runner-Up: Llama-2-70B

  • Second highest parse rate: 65.7%
  • Good consistency across configs
  • Decent CQ coverage: 0.689
  • More parameters don't beat Llama-3.1-8B's efficiency

Key Findings

F1. Model size alone does not predict performance. Llama-3.1-8B (8B params) outperforms both Llama-2-70B (70B) and GPT-5.4 (proprietary large model) on parse reliability.
F2. Instruction following quality matters more than raw capacity for structured output tasks like Turtle generation. Llama-3.1-8B's instruction tuning is superior to older 7B-class models.
F3. The CQ-only prompt maximizes CQ coverage (0.844) but introduces the most hallucination (0.548). Adding the scenario context reduces hallucinations by 24% (cq-only → scenario-cq).
F4. Reasoning-guided prompts (scenario-cq-reasoning) achieve the lowest hallucination (0.367) while maintaining good CQ coverage — the best faithfulness-quality tradeoff.
F5. BLOOM-family models (3B, 7B) fail entirely — 0% parse success. Base language models without instruction tuning are not suitable for ODP generation tasks.
F6. Ground-truth F1 scores are universally low (0.06–0.11), suggesting LLMs diverge significantly in naming conventions from expert ontologists, even when semantically correct.
