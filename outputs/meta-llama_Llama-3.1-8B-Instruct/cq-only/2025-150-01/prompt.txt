You are an ontology engineer. Generate an OWL ontology design pattern (ODP) in Turtle syntax that supports the competency questions below.

Requirements:
- Model only what is needed to answer these CQs; do not add concepts not implied by them.
- Use clear, self-explanatory class and property names.
- Add rdfs:label and rdfs:comment annotations to every class and property.
- Declare a mandatory ontology header: `:Ontology a owl:Ontology ; rdfs:label "..." ; rdfs:comment "..." .`

Use these standard prefixes (declare all that you use):
  @prefix owl:  <http://www.w3.org/2002/07/owl#> .
  @prefix rdf:  <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
  @prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
  @prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .
  @prefix :     <http://example.org/odp#> .

Output format:
1. Turtle ontology wrapped in a ```turtle ... ``` code block.
2. A CQ-to-axiom mapping table: for each CQ, list the classes and properties that enable answering it.

Competency Questions:
- Which MQTT Clients are connected to which Broker?
- Which MQTT NetworkConnections exist, are they TLS-secured, and who initiated/accepted them?
- Which MQTT participants (Clients/Brokers) use which MQTT NetworkConnections?
- Which MQTT Clients with which ClientIDs run on which SOSA platforms?
- Which MQTT Clients are hosting which SOSA systems (sensors/actuators)?
- What host/port is a MQTT Broker configured with?
- Which SOSA sensors publish to which MQTT Topics (observations)?
- Which SOSA actuators listen to which MQTT Topics (commands)?
- Which SOSA FeaturesOfInterest, Properties etc. appear as MQTT TopicSubjects and on which MQTT Topics?
- Which MQTT Topic Filters match a given MQTT Topic?
- Which MQTT Topics are matched by a given MQTT Topic Filter?
- Which MQTT filter patterns (with wildcards) are stored?
- Which MQTT Clients send which MQTT Control Packets?
- Which MQTT PUBLISH/SUBSCRIBE/UNSUBSCRIBE packets were sent (specializations)?
- Which MQTT Brokers receive/forward which MQTT Control Packets?
- Which MQTT Control Packets were sent by which Client (inverse)?
- Which MQTT Publish packets carry Observations for a specific SOSA FeatureOfInterest or Property?
- Which MQTT SUBSCRIBE packets request QoS=2 and for which filters?
- Which MQTT UNSUBSCRIBE packets remove all filters under a certain path (e.g. 'factory/centering/#')?
- Which MQTT Control Packet has which Fixed Header / Variable Header / Payload?
- Which MQTT PUBLISH packet has which MQTT Topic (name) in the Variable Header?
- Which QoS levels are set (in PUBLISH Fixed Header or SubscriptionEntry)?
- Are RETAIN/DUP flags set in PUBLISH?
- Which MQTT Control Packets have which PacketIdentifier?
- Which MQTT SUBSCRIBE payloads contain which SubscriptionEntries?
- Which MQTT Topic Filters (with QoS) are requested by a SubscriptionEntry?
- Which MQTT UNSUBSCRIBE payloads remove which MQTT TopicFilters?
- Which MQTT PUBLISH payloads encode SOSA Observations (or Observation Collections)?
- Which MQTT PUBLISH payloads encode SOSA Actuations (or Actuation Collections)?
- Which fields are encoded in a MQTT payload?
- What content, content type, encoding and delimiter does a MQTT PUBLISH payload have?
- What is the size of a MQTT payload (as QUDT QuantityValue with unit)?
