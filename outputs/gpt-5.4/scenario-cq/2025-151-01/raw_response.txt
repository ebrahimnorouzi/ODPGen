1. The complete Turtle ontology wrapped in a ```turtle ... ``` code block.

```turtle
@prefix owl:  <http://www.w3.org/2002/07/owl#> .
@prefix rdf:  <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
@prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
@prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .
@prefix :     <http://example.org/odp#> .

:Ontology a owl:Ontology ;
  rdfs:label "Evaluation Request Context ODP" ;
  rdfs:comment "An ontology design pattern for representing a formal evaluation request describing a requested action by an assignee on a target asset, together with temporal, spatial, role, and request-capability context used to constrain access evaluation." .

:EvaluationRequest a owl:Class ;
  rdfs:label "Evaluation Request" ;
  rdfs:comment "A formal description of a requested action by an assignee on a target asset, optionally enriched with contextual information for evaluation." .

:Action a owl:Class ;
  rdfs:label "Action" ;
  rdfs:comment "An action that is being requested in an evaluation request." .

:Party a owl:Class ;
  rdfs:label "Party" ;
  rdfs:comment "An entity that can issue an evaluation request." .

:Assignee a owl:Class ;
  rdfs:label "Assignee" ;
  rdfs:comment "The party on whose behalf or about whom the requested action is evaluated." ;
  rdfs:subClassOf :Party .

:Asset a owl:Class ;
  rdfs:label "Asset" ;
  rdfs:comment "A target asset to which the requested action applies." .

:ContextInformation a owl:Class ;
  rdfs:label "Context Information" ;
  rdfs:comment "Additional contextual information that can be included in an evaluation request to further constrain evaluation." .

:TemporalContext a owl:Class ;
  rdfs:label "Temporal Context" ;
  rdfs:comment "Context information concerning time-related constraints relevant to evaluation." ;
  rdfs:subClassOf :ContextInformation .

:SpatialContext a owl:Class ;
  rdfs:label "Spatial Context" ;
  rdfs:comment "Context information concerning location-related constraints relevant to evaluation." ;
  rdfs:subClassOf :ContextInformation .

:RoleContext a owl:Class ;
  rdfs:label "Role Context" ;
  rdfs:comment "Context information concerning role-related constraints relevant to evaluation." ;
  rdfs:subClassOf :ContextInformation .

:RequestCapabilityContext a owl:Class ;
  rdfs:label "Request Capability Context" ;
  rdfs:comment "Context information concerning request-capability constraints relevant to evaluation." ;
  rdfs:subClassOf :ContextInformation .

:requestedAction a owl:ObjectProperty ;
  rdfs:label "requested action" ;
  rdfs:comment "Relates an evaluation request to the action being requested." ;
  rdfs:domain :EvaluationRequest ;
  rdfs:range :Action .

:issuedBy a owl:ObjectProperty ;
  rdfs:label "issued by" ;
  rdfs:comment "Relates an evaluation request to the party issuing it." ;
  rdfs:domain :EvaluationRequest ;
  rdfs:range :Party .

:hasAssignee a owl:ObjectProperty ;
  rdfs:label "has assignee" ;
  rdfs:comment "Relates an evaluation request to the assignee for whom the requested action on the target asset is described." ;
  rdfs:domain :EvaluationRequest ;
  rdfs:range :Assignee .

:targetAsset a owl:ObjectProperty ;
  rdfs:label "target asset" ;
  rdfs:comment "Relates an evaluation request to the asset that is the target of the requested action." ;
  rdfs:domain :EvaluationRequest ;
  rdfs:range :Asset .

:hasContextInformation a owl:ObjectProperty ;
  rdfs:label "has context information" ;
  rdfs:comment "Relates an evaluation request to additional contextual information that further constrains evaluation." ;
  rdfs:domain :EvaluationRequest ;
  rdfs:range :ContextInformation .

:issuedAt a owl:DatatypeProperty ;
  rdfs:label "issued at" ;
  rdfs:comment "Relates an evaluation request to the date-time at which it was issued." ;
  rdfs:domain :EvaluationRequest ;
  rdfs:range xsd:dateTime .
```

4. Intentionally excluded concepts:

- `Employee`
  - Excluded because the scenario mentions “only to employees” as an example of role-based constraint, but the CQs only require support for contextual categories, not a full role taxonomy. Adding `Employee` would introduce a specific domain concept not necessary to answer the CQs.

- `Weekday`
  - Excluded because the scenario requires temporal context support, but not a detailed calendar ontology. `:TemporalContext` is sufficient for the requested ODP scope.

- `EU`
  - Excluded because the scenario requires spatial context support, but not a geopolitical region model. `:SpatialContext` is sufficient for the requested ODP scope.

- Explicit policy, permission, or decision outcome classes
  - Excluded because the scenario is about the evaluation request and its context, not about modeling authorization policies or resulting allow/deny decisions.

- Detailed capability taxonomy
  - Excluded because the scenario only requires the presence of request-capability context as a category, not a decomposition of capabilities into finer-grained concepts.
