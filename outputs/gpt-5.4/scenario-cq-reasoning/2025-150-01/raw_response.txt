1. **Reasoning for steps 1–6**

### Step 1. Atomic requirements
- The ontology must represent MQTT participants, at least Clients and Brokers.
- The ontology must represent network connections between MQTT participants.
- A network connection must support indicating whether it is TLS-secured.
- A network connection must support indicating which participant initiated it.
- A network connection must support indicating which participant accepted it.
- The ontology must represent which MQTT participants use which network connections.
- The ontology must represent MQTT Clients and their ClientIDs.
- The ontology must represent which MQTT Clients run on SOSA Platforms.
- The ontology must represent which MQTT Clients host SOSA Systems.
- The ontology must distinguish hosted SOSA Systems such as Sensors and Actuators.
- The ontology must represent MQTT Brokers configured with host and port.
- The ontology must represent MQTT Topics.
- The ontology must represent MQTT Topic Filters.
- The ontology must represent filter patterns, including wildcard-containing patterns.
- The ontology must represent matching relations between Topic Filters and Topics.
- The ontology must represent TopicSubjects appearing on MQTT Topics.
- TopicSubjects must be able to denote SOSA FeaturesOfInterest and observable/actuatable properties.
- The ontology must represent MQTT Control Packets.
- The ontology must represent packet specializations including PUBLISH, SUBSCRIBE, and UNSUBSCRIBE.
- The ontology must represent which Clients send Control Packets.
- The ontology must represent which Brokers receive Control Packets.
- The ontology must represent which Brokers forward Control Packets.
- The ontology must represent packet structure: Fixed Header, Variable Header, and Payload.
- The ontology must represent which packet has which Packet Identifier.
- The ontology must represent PUBLISH packets with a Topic in the Variable Header.
- The ontology must represent QoS values used in PUBLISH fixed headers and subscription entries.
- The ontology must represent RETAIN and DUP flags in PUBLISH.
- The ontology must represent SUBSCRIBE payloads containing Subscription Entries.
- A Subscription Entry must represent a requested Topic Filter and requested QoS.
- The ontology must represent UNSUBSCRIBE payloads removing Topic Filters.
- The ontology must represent PUBLISH payloads encoding Observations or Observation Collections.
- The ontology must represent PUBLISH payloads encoding Actuations or Actuation Collections.
- The ontology must represent fields encoded in a payload.
- The ontology must represent payload content, content type, encoding, and delimiter.
- The ontology must represent payload size as a quantity value with unit.
- The ontology should align observation and actuation descriptions with MQTT transport semantics using reusable patterns.

### Step 2. Candidate classes and properties
- Classes: `MQTTParticipant`, `MQTTClient`, `MQTTBroker`.
- Classes: `NetworkConnection`.
- Properties: `usesConnection`, `initiatedBy`, `acceptedBy`, `tlsSecured`.
- Datatype property: `clientId`.
- Reused/general classes for SOSA alignment: `Platform`, `System`, `Sensor`, `Actuator`, `Observation`, `Actuation`, `FeatureOfInterest`, `Property`.
- Properties: `runsOnPlatform`, `hostsSystem`, `publishesToTopic`, `listensToTopic`.
- Classes: `Topic`, `TopicFilter`, `TopicSubject`.
- Properties: `filterPattern`, `matchesTopic`, `hasTopicSubject`, `denotesFeatureOfInterest`, `denotesProperty`.
- Classes: `ControlPacket`, `PublishPacket`, `SubscribePacket`, `UnsubscribePacket`.
- Properties: `sentBy`, `receivedBy`, `forwardedBy`.
- Classes: `FixedHeader`, `VariableHeader`, `Payload`.
- Properties: `hasFixedHeader`, `hasVariableHeader`, `hasPayload`, `packetIdentifier`.
- Property: `topicName` from variable header to topic.
- Datatype properties on fixed header: `qosLevel`, `retainFlag`, `dupFlag`.
- Classes: `SubscribePayload`, `UnsubscribePayload`, `PublishPayload`.
- Class: `SubscriptionEntry`.
- Properties: `hasSubscriptionEntry`, `requestedTopicFilter`, `requestedQoS`, `removesTopicFilter`.
- Classes: `ObservationCollection`, `ActuationCollection`.
- Properties: `encodesObservation`, `encodesObservationCollection`, `encodesActuation`, `encodesActuationCollection`.
- Class: `PayloadField`.
- Property: `encodesField`.
- Datatype properties: `content`, `contentType`, `characterEncoding`, `delimiter`.
- Classes: `QuantityValue`, `Unit`.
- Property: `payloadSize`, `numericValue`, `unit`.

### Step 3. Draft axioms
- `MQTTClient ⊑ MQTTParticipant`, `MQTTBroker ⊑ MQTTParticipant`.
- `MQTTClient ⊓ MQTTBroker ⊑ ⊥`.
- `usesConnection` domain `MQTTParticipant`, range `NetworkConnection`.
- `initiatedBy` domain `NetworkConnection`, range `MQTTParticipant`, max 1.
