## Documentation

- **Intent:** This pattern models secured access to a relational database where the access is carried out using an SQL query.

- **Covered requirements:**
  - Models a relational database.
  - Models SQL queries used to query the database.
  - Models access to the database.
  - Models security controls that secure such access.
  - Connects access to the database being accessed.
  - Connects access to the SQL query used.
  - Connects SQL queries to the relational database they query.
  - Connects access to the security control securing it.

- **Known assumptions and exclusions:**
  - The scenario does not specify users, roles, permissions, authentication methods, or authorization policies, so they are excluded.
  - The pattern treats “securing access” generically via `SecurityControl` without distinguishing control types.
  - No individuals or operational details of SQL syntax, database schema, sessions, or network infrastructure are modeled.
  - Disjointness is asserted only among the four core classes because they represent clearly different kinds of things in this scenario.
