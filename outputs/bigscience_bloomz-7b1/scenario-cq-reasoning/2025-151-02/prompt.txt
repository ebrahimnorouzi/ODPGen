You are an ontology engineer. Create an OWL ontology design pattern (ODP) in Turtle syntax.

Before writing, reason through these steps internally (do NOT write them out yet):
1. Extract atomic requirements from the scenario (one sentence each).
2. Propose candidate classes and properties per requirement.
3. Draft axioms (subclass, domain, range, cardinality, disjointness).
4. For each CQ, verify which axioms enable answering it; note gaps.
5. Add/refine axioms to cover uncovered CQs.
6. Remove classes/properties not traceable to any requirement or CQ.

Constraints:
- Declare every class with `a owl:Class`, every property with `a owl:ObjectProperty`, `a owl:DatatypeProperty`, or `a owl:AnnotationProperty`.
- Do NOT create individual instances (e.g. `:SomePerson a :Person`); output schema axioms only.
- Add rdfs:label and rdfs:comment to every class and property.
- Declare a mandatory ontology header: `:Ontology a owl:Ontology ; rdfs:label "..." ; rdfs:comment "..." .`
- Keep modeling minimal and reusable; do not assert facts not implied by the scenario or CQs.

Use these standard prefixes (declare all that you use):
  @prefix owl:  <http://www.w3.org/2002/07/owl#> .
  @prefix rdf:  <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
  @prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
  @prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .
  @prefix :     <http://example.org/odp#> .

Output format — strictly in this order, nothing before item 1:
1. The complete Turtle ontology wrapped in a ```turtle ... ``` code block. Output this FIRST, before any explanation.
2. Reasoning summary: one bullet per step 1–6 (keep each to one line).
3. Traceability table: for each requirement/CQ, list the axiom(s) that cover it.

Scenario:
Knowledge representing real-world information aiding the evaluation of ODRL Policies. Bob wants to have access to a certain video stream, but only needs access to minutes 4 to 9, for the purposes of an academic research project.

Competency Questions:
- What is the current time?
- What is the location of a party?
- What assets are part of the asset collection of the policy that is being evaluated?
- Which parties are part of the party collection of the policy that is being evaluated?
- What actions were already performed or attempted?
- How many times has a rule been exercised?
- What information is available about an event that has occurred?
- How long has a rule been exercised?
- Which recipients or categories of recipients can receive the result of the rule that has been exercised?
- Has a financial payment been made? What was the amount paid?
