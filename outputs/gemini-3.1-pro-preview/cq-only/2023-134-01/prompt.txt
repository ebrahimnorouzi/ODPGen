You are an ontology engineer. Generate an OWL ontology design pattern (ODP) in Turtle syntax that supports the competency questions below.

Requirements:
- Model only what is needed to answer these CQs; do not add concepts not implied by them.
- Use clear, self-explanatory class and property names.
- Declare every class with `a owl:Class`, every property with `a owl:ObjectProperty`, `a owl:DatatypeProperty`, or `a owl:AnnotationProperty`.
- Do NOT create individual instances (e.g. `:SomePerson a :Person`); output schema axioms only.
- Add rdfs:label and rdfs:comment annotations to every class and property.
- Declare a mandatory ontology header: `:Ontology a owl:Ontology ; rdfs:label "..." ; rdfs:comment "..." .`

Use these standard prefixes (declare all that you use):
  @prefix owl:  <http://www.w3.org/2002/07/owl#> .
  @prefix rdf:  <http://www.w3.org/1999/02/22-rdf-syntax-ns#> .
  @prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#> .
  @prefix xsd:  <http://www.w3.org/2001/XMLSchema#> .
  @prefix :     <http://example.org/odp#> .

Output format — strictly in this order, nothing before item 1:
1. The complete Turtle ontology wrapped in a ```turtle ... ``` code block. Output this FIRST, before any explanation.
2. A CQ-to-axiom mapping table: for each CQ, list the classes and properties that enable answering it.

Competency Questions:
- What is the unique identifier of the policy?
- Who is the creator of the policy?
- When was the policy issued?
- Who is the assignee of the policy?
- What application/service is being used to access the data?
- What access mode is being requested?
- What personal data is being accessed?
- What is the purpose for accessing the data?
