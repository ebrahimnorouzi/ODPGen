### Documentation

**Intent:** 
To model the security and access control mechanisms for entities querying a relational database using Structured Query Language (SQL).

**Covered requirements:**
*   Representation of a Relational Database (RDB) as the core resource.
*   Representation of Structured Query Language (SQL) queries used to interact with the database.
*   Modeling the relationship of an RDB being queried via SQL (`isQueriedVia` / `queriesDatabase`).
*   Modeling the security aspect of access (`AccessPolicy` and `isSecuredBy`), ensuring that interactions with the database are governed by a defined policy.

**Known assumptions and exclusions:**
*   **Assumption:** The concept of "access" inherently implies an actor or subject requesting that access. Therefore, an `Accessor` class was introduced to logically complete the pattern of issuing queries and being subject to security policies.
*   **Exclusion:** The internal schema of the relational database (e.g., tables, columns, rows, primary keys) is excluded as it falls outside the strict scope of the scenario.
*   **Exclusion:** Specific access control paradigms (like Role-Based Access Control or Attribute-Based Access Control) are not explicitly modeled to keep the pattern minimal and universally applicable to the scenario.
